# Memories Studio 开发文档

> 仿 MemoriesOnTV4 的 Windows 桌面视频编辑客户端
> 输入照片/视频/音乐 → 人脸为中心的自动运镜 + 常用转场 → 导出 HD/2K/4K MP4
> 文档版本：v0.5.4（2026-11-12）

---

## 1. 项目概述

Memories Studio 是一款面向普通用户的照片视频制片工具，核心卖点是**零手工剪辑**：

- 把一批旅游照片/视频拖进素材库，程序自动完成：素材探测（分辨率/时长/原声）→ 人脸检测（YuNet）→ 按人脸构图生成运镜（推拉/平移）→ 自动转场 → 配乐铺满全片。
- 时间轴支持拖动排序、多选、搓动播放头、边缘自动滚动等手工微调。
- 导出走 ffmpeg 管线，画质优先（默认 CPU libx264），支持 1080p/2K/4K。
- 提供免管理员的安装程序（内置 ffmpeg / LibVLC / .NET 运行库）与 .msproj 工程文件关联。

## 4. 构建与运行环境（重要约定）

- 本机只有 .NET 6 运行时；**.NET 8 SDK 装在用户目录** `C:\Users\Lenovo\.dotnet`，`dotnet` 命令一律用该绝对路径；运行 Debug 版需 `DOTNET_ROOT=C:\Users\Lenovo\.dotnet`。
- NuGet 官方源不通，走华为镜像（仓库根 `NuGet.config`）。
- 发布主程序：
  ```
  dotnet publish -c Release -r win-x64 --self-contained true
    -p:PublishSingleFile=true -p:IncludeNativeLibraries=true
  ```
  **注意**：WPF 原生 DLL（wpfgfx/PresentationNative/D3DCompiler/vcruntime 等）不会打进单文件，必须把 publish 目录下的 `*.dll` 一并拷入 dist。
- 发布安装器：先 `python tools/make_payload.py <载荷目录> src/MemoriesStudio.Setup/payload.zip`（载荷 = dist 全部 + `ffmpeg\ffmpeg.exe`，剔除 32 位 libvlc、*.lib 和 dist 里残留的旧安装包），再对 Setup 项目执行同上 publish，得约 302MB 单文件；版本号改 `MemoriesStudio.Setup.csproj` 的 Version 与 `Installer.cs` 的 `AppInfo.DisplayVersion`。
- ffmpeg/ffprobe 本机开发副本在 `D:\src\bat\`（PATH 中）。

## 5. 主程序架构与核心流程

### 5.1 导入与探测
1. 素材入轨前 **必须 await 探测完成**（分辨率/时长/是否原声/缩略图），否则片段拿到 0 值；探测晚到要按路径回填同素材的所有片段。
2. 探测通道：LibVLC 元数据 → OpenCV VideoCapture → ffprobe 兜底（30s 超时）。
3. **ffprobe 输出是 UTF-8**，`ProcessStartInfo` 必须显式设 `StandardOutputEncoding/StandardErrorEncoding = UTF8`，否则中文路径被按 GBK 拆字导致 JSON 解析失败、探测返回 null、视频回退默认 4/5 秒时长。
4. 打开旧工程时重新探测并迁移：旧版把视频一律存 4 秒，需把"4s/5s 且入点=0"的片段恢复实际时长（用户裁剪过的只夹取不重置）。
5. **HEIC/HEIF（v0.5.6 起）**：OpenCV 与 WPF 都解不开（WPF 依赖系统 HEIF 扩展，异机不可靠），统一走 `MediaSource.Resolve`——首次解码时用捆绑 ffmpeg 把 HEIC 转成缓存 JPG（`%LOCALAPPDATA%\MemoriesStudio\media_cache`，键=路径|大小|mtime 的 SHA1），探测/缩略图/预览/人脸检测/导出全部读缓存。注意两个坑：① ffmpeg 输出文件名必须以 .jpg 结尾（容器格式靠扩展名推断，.tmp 会报 Invalid argument）；② HEIC 里除主图还有缩略图/深度图等几十条流，**不要显式 -map**，默认流选择器才会选主 tile grid。

### 5.2 人脸检测（FaceDetector）
- **模型来源优先级（v0.5.5 起，务必保持）**：用户目录副本 `%LOCALAPPDATA%\MemoriesStudio\models` → 安装目录随包模型 `AppContext.BaseDirectory\models` → 网络下载（仅当前两者都缺时才尝试）。启动时先做"随包 → 用户目录"的本地补齐（失败只记日志），**任何网络步骤都不得阻挡本地模型可用**。
  - 历史 bug：早期实现把"下载 Haar 级联"放在最前面且同一个 try 里，网络失败（离线/raw.githubusercontent 被墙）→ 直接跳 catch → 随包 YuNet 的复制被跳过 → 全新电脑上人脸检测全线退化（表现为"模型不工作"）。
  - 装载失败（文件损坏/半截）时按候选列表依次回退（用户目录 → 随包目录），全失败才标记 `_yunetBroken` 放弃本轮。
- **主力：YuNet（FaceDetectorYN ONNX）**。OpenCvSharp 无托管封装且原生 DLL 只有 C++ 符号 → 用 `OpenCvSharp.Dnn` 手工移植官方后处理：12 个输出逐名 Forward（多输出 Forward(List<Mat>, string[]) 包装有 bug 恒返回空）；score=sqrt(cls*obj)；bbox 布局 [1,N,4] 锚点优先；NMS eta=1 topK=5000；输入补边到 32 倍数、blobFromImage swapRB=true 无归一化。模型从 media.githubusercontent.com 下载（raw 是 LFS 指针），dist 捆绑 `models/` 兜底离线。
- 检测分辨率 1024，耗时约 1.2s/张；**0 hits 即判无人，不回落 Haar**（防塔身/碑框花纹误检）。
- 历史：res10 SSD Caffe 模型在 OpenCvSharp 4.10 下输出恒为均匀噪声（已弃用）；Haar 级联曾作主力（FaceHV=1，需 NetLock 加锁 + 聚类 + 肤色验证 + 面积上限），现仅保留代码路径。
- 语义版本：`Clip.FaceHV=2` 标记 YuNet 语义；打开旧工程（后台）与导出（BuildPlan 同步）自动迁移重检。
- **异机排障入口**：`MemoriesStudio.exe --facedebug <图> [offline]`（offline = 禁网，只验证随包模型）；日志 `%TEMP%\memories_face.log` 记录模型路径/复制/装载结果，状态栏在模型缺失时也会提示。

### 5.2.1 动图（<2 秒视频）按图片入轨
手机实况照片导出的视频往往只有 1 秒左右，按视频入轨只有一两秒、转场都放不下。规则：**入轨时若视频时长 < 2 秒，用 ffmpeg 在时长 1/2 处截一帧，按图片片段入轨**（4 秒、可运镜/转场、走人脸检测）。
- 截帧缓存：`MediaSource.ExtractStill(video, t)` → `%LOCALAPPDATA%\MemoriesStudio\media_cache\<hash>.jpg`，键含 视频路径|大小|mtime|t，同一视频同一时刻只截一次。
- `Clip.StillFrom` 存原始视频路径（随工程保存）；`Clip.SourcePath` 指向截帧 JPG。
- 缓存被清理/换机后自动重建：打开工程（后台 → Dispatcher 回填）与导出 `BuildPlan` 都会调 `MediaSource.RebuildMissingStills`。
- 素材库仍显示原视频（`MediaAsset.InfoText` 提示"动图 · x.xs（按图片入轨）"）；打开工程时 `RebuildAssetsFromProjectAsync` 用 `StillFrom` 还原素材，不会多出一堆哈希命名的图片素材。
- 坑：`-ss` 放在 `-i` 前快速定位；输出临时文件必须以 `.jpg` 结尾（容器格式靠扩展名推断）。

### 5.3 运镜（MotionMath，语义 v3）
用户五条规则（`Clip.MotionV=3`）：
1. 有人 + 横向 → 轻推拉 ≤8%，人脸屏幕位置尽量=0.5、头顶留 2%、缩放 ≤1/(fh*3.6)，最多追加 1.3×（CenterBoost）。
2. 无人 + 横向 → cover 静止。
3. 无人 + 竖幅 → 上下滑动（原图上下各留 10%）+ 时长 +1s（`Clip.AutoDurBonus` 幂等补差额）。
4. 有人 + 竖幅 → 滑到人脸横带静止（PanV 纵向平移）。
5. 稳定随机：`Random(Id.GetHashCode() ^ index * 7919)`，保证同工程重开结果一致。

- 头部高度语义：检测框只覆盖眉→下巴，构图用 ×1.45（含头发）。
- **竖幅照片纵向平移（PanV=1）**：判定 `ih ≥ iw*0.95` 且脸框超出画布高 8%；或横向 4:3 照片的脸被 cover 裁出画面（FaceOutOfView）。`Clip.FaceSY` 存原图归一化人脸 Y（画布坐标会失真）；焦点 Y 允许 [-2,3]。
- **关键不变式**：`MotionMath.WindowTop` 与导出 zoompan、预览 MatrixTransform 的 clamp 公式完全一致（天然不露黑边）；导出表达式与 MotionMath.At 各留 FaceY 基线修正兜底。
- 旧工程按 `MotionV<2` 在 ExportEngine.BuildPlan 与打开工程时重算。

### 5.4 预览
- **暂停态**：VideoGrabber（OpenCV seek 单帧约 600ms/帧，ffmpeg 兜底）。
- **播放态**：VideoFramePlayer 流式解码；拖动进度条走 RequestScrubFrame → PumpScrubAsync 去抖泵，只渲染最新位置。
- **照片 cover 布局**：不能用 `Stretch=UniformToFill`（溢出内容锚定左上角不居中，预览与导出不一致的根因）；改显式 cover 布局（host.Width/Height=cover 尺寸、ClipToBounds=false、img.Stretch=Fill、MatrixTransform）。
- **PanV 预览黑带坑**：WPF Image 高度超过父容器测量 slot 时绘制被钳制到 slot 高度（布局属性全正确但渲染像素不符）；修复是把宿主 Grid 的 Height 也撑到 cover 高。
- 预览全静音（v0.4 起删除 AudioChannel）：本机无 WMP 组件，WPF MediaPlayer 打开视频报错、NAudio 解容器失败，故原声只在剪辑对话框（LibVLC）与导出中存在。

### 5.5 时间轴（TimelineControl，自绘）
- FrameworkElement + OnRender + 自管鼠标，零布局开销；PressMode 状态机（None / Scrub / MaybeDragClip / DragClips）。
- **拖动排序落点**：按 `ComputeStarts` 真实起点数"中点在鼠标左侧"的剩余片段 = 插入下标（不能用剔除拖动块后的前缀和——会偏前一格）。
- **边缘自动滚动**：控件在 ScrollViewer 内时 `ActualWidth` 是内容总宽，可视区必须用 `[HorizontalOffset, HorizontalOffset+ViewportWidth]`；边界 60px，最高 20px/拍。
- **跨屏拖放**：落手后 `ClipsReordered → RefreshAfterTimelineEdit → UpdateTransportUi → EnsurePlayheadVisible` 会用旧 _time 把视口拽回开头；修复 = `IsDragging`（含落手后 350ms `_dragSettleUntil`）时短路 + 落手前记录/还原 HorizontalOffset。
- 自定义拖动光标：DrawingVisual → RenderTargetBitmap → 组 .cur（ICONDIRENTRY 的 planes/bitCount 字段即热点 xy，biHeight=2×高），按（数量, 是否全视频）缓存。

### 5.6 剪辑对话框（TrimWindow）
- LibVLC 播放（`EnableHardwareDecoding=false`，WPF VideoView + D3D11 易黑屏）。
- 单个 TrimRangeBar：左把手=入点、右把手=出点、中间圆点=播放位置（钳制区间内）。
- **LibVLC 3.x 要点**：Parse 后须轮询 `ParsedStatus==Done`（await 挂死）；seek 后 400ms 内 `Time` 仍回旧值（SeekTo 带时间戳护栏）；`Stop()` 等 vout 拆卸放 UI 线程偶发卡死（OnClosed 只断 `Video.MediaPlayer`，Stop/Dispose 放后台）；事件回调不得 Dispatcher.Invoke 与 UI 线程互等（用 DispatcherTimer 轮询 Time）；Media+Play 与 Dispose 都放后台线程。
- 打开自动定位入点：`:start-time=N` 起播即暂停 + 校验补 seek ≤3 次。

### 5.7 配乐
- `ProjectFile.MusicPaths`（设置对话框管理）；旧 MusicPath/AudioItems 由 MigrateLegacyMusic 并入。
- 导出时 BuildMusicSlots 顺序循环铺满 + 每段 afade 淡入淡出 1s + 仅照片段出声（视频段静音）。
- **坑**：asetpts 把音乐段 t 归零，视频段让位区间须先求交再减 item.Start 换算成本地时间。

### 5.8 导出（ExportEngine）

**大工程必须分块渲染（≥13 个片段即触发，单块上限按分辨率自适应）。** 任意时刻 ffmpeg 只在合成相邻 2 个素材的转场，但把全部输入塞进一条命令会撞两个硬限制：

1. **Windows 命令行上限 32767 字符**：每张照片一个 `-i`，上千素材时 `CreateProcess` 直接失败（.NET 报错文案是"An error occurred trying to start process … with working directory …"，与工作目录无关，极易误判）。
2. **滤镜队列内存爆炸**：滤镜图会把已生成的帧堆在队列里等下游消费，实测约每片段 24 帧（720p 60 片段≈2GB，300 片段≈5GB 并持续增长，1080p/4K 更甚）。

因此分三步：

1. **分块渲染**：块大小 = `clamp(2.4GB / (W*H*1.5*24), 12, 60)`（720p→60、1080p→32、4K→12）。相邻块**共享一个边界片段**：块 N 渲染 `[b_N … b_{N+1}]`，输出用 `-t` 裁到 `starts[b_{N+1}] + td[b_{N+1}]`（边界片段进入转场刚结束）；块 N+1 从同一片段重渲，但首片段时长改为 `dur - td`（跳过已渲染的进入转场）。所有切割点都帧对齐，拼接后逐帧连续、无重复无丢帧。
2. **无损拼接**：`-f concat` 清单 + `-c:v copy`（流复制，绝不重编码）。注意 mp4 分块各自带时长，**不能**像照片清单那样重复末尾文件（会多播末块、多出帧）。
3. **终段混音**：视频原声重新引用原视频文件（数量少）取音频流、配乐按 MusicPaths 铺满，`amix` 后编码 AAC，视频流仍 `copy`。

块内的照片输入也不逐张 `-i`，而是写进 **concat 清单文件**（每张一行 `file` + `duration`），滤镜里用 `trim=start=…:end=…,setpts=PTS-STARTPTS` 取单帧再进运镜链；PanV 竖幅还要在 crop 前插 `zoompan=z=1:d=frames` 把单帧复制成多帧（crop 的逐帧变量 `n` 才有变化）。这样照片数量再多，命令行也只有常数长度。

- 照片链：zoompan（`s={超采样}`，内置缩放器非 lanczos）+ 外部 `scale={W}:{H}:flags=lanczos`；PanV 用 `crop=w:h:x:'clip(y0+(y1-y0)*e,0,in_h-out_h)'`（crop 的 y 逐帧求值、变量是 n 不是 on、表达式必须单引号包裹否则逗号切断滤镜链）。
- 转场拼接用**平衡二叉树**而非链式：链式在 900 片段时每帧穿透约 450 层滤镜，耗时超线性（100 张 30s → 300 张 142s）。树形与链式在转场互不重叠时数学等价（接缝转场 = 右组首片段的进入转场，偏移 = 左组长度 - 转场时长），每帧只穿透 log₂N 层。
- 编码默认 CPU libx264 crf16（画质优先，实测 NVENC 运动内容丢细节 -16%）；GPU h264_nvenc 可选（p7 + tune hq + spatial/temporal-aq + lookahead20 + bf2 + multipass fullres）。
- 无头导出 `--export` 不经过主窗口：旧数据迁移、相对路径按工程目录解析都要在 App.RunHeadlessExport/BuildPlan 再做一遍。
- 画质量化：LapVar（4 邻域拉普拉斯方差）对比；**对微信压缩图会失真**（压缩锐化 halo 使指标虚高），须目视比对。
- 诊断开关：`MEMORIES_KEEP_CHUNKS=1` 保留分块中间产物（`%TEMP%\ms_chunks_*`），逐个 ffprobe 帧数即可定位块边界问题。

## 6. 数据模型（.msproj）

JSON 文本，根对象 `ProjectFile`：素材列表（绝对/相对路径）、片段列表（Clip）、配乐 MusicPaths、画布设置、让位开关等。

**Clip 的语义版本字段**（打开/导出时自动迁移旧数据）：

## 8. 安装器设计（MemoriesStudio.Setup）

- WinForms 自包含单文件，载荷 payload.zip 以 EmbeddedResource 嵌入；运行时 `GetManifestResourceStream` → （不可 seek 时先落临时文件）→ ZipArchive 流式解压，按字节推进度。
- 安装目录默认 `%LOCALAPPDATA%\Programs\MemoriesStudio`（免管理员）。
- 快捷方式：IShellLink COM P/Invoke（开始菜单 + 桌面可选）。
- 文件关联（HKCU\Software\Classes，免管理员）：`.msproj` → ProgId `MemoriesStudio.Project`（DefaultIcon + shell\open\command）；同时写 `Software\MemoriesStudio\Capabilities` + `RegisteredApplications`，使程序出现在「设置→默认应用」。**Win10/11 UserChoice 有哈希保护，安装器无法静默抢占**，完成页提供直达「默认应用」的按钮。
- uninstall.exe = 安装器自身复制；卸载先结束进程（KillRunning）→ 删快捷方式 → 清注册表 → 延迟 bat（ping 3s + rmdir）删自身所在目录。
- 安装前检测目标目录已装 → 询问覆盖升级；目标目录不可写 → 明确报错并给建议；程序运行中会锁文件 → 先结束。
- 完成页状态机：ApplyInstalledState()（解除忙碌 → 锁路径 → 启用「完成」/隐藏「退出」/显示立即启动）；点击「完成」= 启动主程序（可选）+ Hide/Close/Application.Exit 确保进程退出。

## 9. 关键坑清单（按主题速查）

**编码/进程**
1. ffprobe 输出必须显式 UTF-8（中文路径被 GBK 拆字 → 探测 null）。
2. ffmpeg 加 `-nostdin` 防 GUI 无 stdin 挂死；**ffprobe 不能加**（gyan essentials 不支持，直接无输出）。
3. 外部进程结果回 UI 必须 Dispatcher.Invoke。

**WPF**
4. StaticResource 不支持前向引用——资源一律放 App.xaml 最前。
5. Image 超出父容器测量 slot 时绘制被钳制（黑带根因之一）；宿主 Height 一并撑到 cover 高。
6. Stretch=UniformToFill 溢出锚定左上角不居中——cover 布局必须显式矩阵。
7. XAML 初始化 Slider.Minimum 会触发 ValueChanged，处理器需 _uiReady 守卫。

**LibVLC**
8. Parse 后轮询 ParsedStatus；seek 400ms 护栏；Stop/Dispose 放后台；关闭硬解；事件回调不 Invoke 回 UI（改轮询）。

**OpenCV / YuNet**
9. CascadeClassifier 并发必须加锁；多输出 Forward(List<Mat>, string[]) 有 bug，逐名 Forward。
10. Haar 误检要聚类 + 肤色验证 + 面积上限；YuNet 0 hits 即判无人。
11. **模型引导必须"本地优先"**：随包模型（安装目录 models）→ 用户目录 → 网络；网络步骤要各自独立 try，不能让级联下载失败连带跳过随包模型复制（v0.5.5 前的"新电脑模型不工作"根因）。装载失败也要在候选路径间回退。
12. OpenCvSharpExtern.dll 是静态 CRT 构建（只依赖 kernel32/ole32 等系统 DLL），**不需要 VC++ 运行库**——异机异常别先怀疑 VC redist。

**导出/画质**
11. zoompan 内置缩放器非 lanczos → 超采样 + 外部 lanczos。
12. crop 表达式单引号包裹、变量 n 不是 on。
13. 微信压缩素材（≈2MP 照片 / 960×720 视频）上采样到 1080p 就是"DVD 清晰度"——先 ffprobe 素材分辨率再谈"导出模糊"。

**安装器**
14. WinForms 枚举叫 MessageBoxIcon；单文件发布下资源流不可 seek 先落盘；WindowsDesktop 单文件仍会在输出目录漏 WPF 原生 dll（WinForms 用不到）。
15. --selftest 会清真实关联，跑完要静默重装恢复。
16. 卸载删除目录要用**带重试的 bat**（`ping` 等待 + 循环 `rmdir /s /q` 最多 20 次）：uninstall.exe 自身在目录内，且杀软/句柄占用会让一次性 rmdir 失败，只剩 uninstall.exe 残留在安装目录。
